# StudentFlow — Студенттерді есепке алу жүйесі

**Лабораторные работы №9–10 и №12.** Локальный учебный сайт Python / FastAPI / SQLite с клиентским модулем JavaScript + DOM + localStorage. Интерфейс на казахском языке.

## Что добавлено для №10

После входа под любой существующей ролью откройте «Оқу жоспары · №10» в левом меню:

1. **http://127.0.0.1:8000/lab10** — каталог из JS-массива; форма читает тему, часы и приоритет, затем сохраняет JSON.
2. **http://127.0.0.1:8000/lab10/plan** — отдельная страница читает localStorage и строит таблицу и суммы через DOM.
3. **http://127.0.0.1:8000/lab10/map** — блок-схема переходов всего сайта и схема данных.

План содержит только коды готовых учебных тем, часы 1–40 и приоритет. Он общий для этого браузера и адреса сайта, не связан с аккаунтом. ФИО, логины, пароли, сессии и оценки не записываются в localStorage. Исходная SQLite и серверные права не изменены.

**Материалы для сдачи:**
- `docs/LAB10_REPORT.md` — отчёт на казахском с фрагментами настоящего кода.
- `docs/NAVIGATION.md` — полная карта переходов.
- `docs/SCREENSHOT_SCENARIOS.md` — пошаговые сценарии и подписи для скриншотов.
- `docs/VERIFICATION.md` — что реально проверено и что осталось проверить.
- `tests/check_lab10_logic.cjs` — проверки логики без сторонних Node-пакетов.

**Скриншоты необходимо снять после запуска.** В текущей среде Chromium не запустился; успешный браузерный прогон и наличие снимков не заявляются. Все ограничения указаны в `docs/VERIFICATION.md`.

При повторном выборе темы её запись обновляется без дублирования. План переживает обновление страницы. Одновременное редактирование в нескольких вкладках не поддерживает атомарное слияние; для демонстрации используйте одну вкладку.

## Зертханалық жұмыс №12 · Қауіпсіздік

Қауіпсіздік модулі іске қосылған соң сол мәзірдегі **«Қауіпсіздік · №12»** сілтемесін ашыңыз:

- `/register` — Argon2 хэшімен тіркелу, оқу тобын көрсету; рөлді сервер `student` етіп тағайындайды және жаңа аккаунтқа бірден кіргізеді.
- Кейін қайта кіру үшін тіркелгенде таңдаған username мен парольді қолданыңыз. Username — email емес, тіркелу формасындағы логин.
- `/account` — аккаунт мәліметтері мен қазіргі парольді растау арқылы парольді ауыстыру; ауыстырған соң барлық алдыңғы сессиялар жабылады.
- `/admin` қолданушыларды аты-жөні/логин бойынша іздейді; `/teacher` бағалар журналын пән және мәтін бойынша сүзеді.
- Бір логинге 15 минут ішінде 8, бір IP-ден 30 қате кіруге дейін уақытша шектеу қойылады. Бірнеше сервер процесі қолданылса, лимитерді Redis сияқты ортақ сақтау орнына көшіру керек.
- `py backup_db.py` SQLite сақтық көшірмесін жасап, `integrity_check` арқылы тексереді.
- `/lab12` — рөлдер, серверлік қолжетімділік тексерулері, CSRF және SQL-инъекцияға қауіпсіз тест-пішіні.
- `/admin#users` — әр пайдаланушының рөлін көру/әкімші рөлін басқару (тек admin).
- Студент немесе оқытушы `/admin` ашса, өз кабинетіндегі `/dashboard` бағытына қайтарылады. Рұқсат серверде де тексеріледі.
- `' OR 1=1 --` деген тест мәтінін `/lab12` іздеу өрісіне енгізіңіз: ол SQL кодына біріктірілмей, параметр ретінде өңделеді.

Қорғауға арналған толығырақ түсіндірме мен сценарийлер: `docs/LAB12_REPORT.md`. Тест/стиль тексерулерін орнату және іске қосу: `py -m pip install -r requirements-dev.txt`, `py -m pytest -q`, `py -m ruff check app.py migrations.py backup_db.py tests`. Браузерлік сынаққа Chromium орнатып `py -m playwright install chromium`, кейін `py tests/e2e_studentflow.py` орындаңыз. Резервтеу, қалпына келтіру және production конфигурациясы: `docs/OPERATIONS.md`. Дерекқордың тексерілген сақтық көшірмесі: `py backup_db.py` (`backups/` ішінде жасалады); қалпына келтіру алдында серверді тоқтатыңыз.

## Быстрый запуск в Windows (VS Code)

1. Распакуй архив. Открой папку `student_site` в VS Code (`File → Open Folder`).
2. Открой **Terminal → New Terminal** и выполни последовательно (либо дважды нажми `setup_windows.bat`, а после настройки — `start_windows.bat`):

   ```powershell
   py -m pip install -r requirements.txt
   py set_passwords.py
   py -m uvicorn app:app --reload
   ```

3. Открой **http://127.0.0.1:8000** в браузере.
4. Войди под одним из логинов, задав пароли на шаге 2:

   | Логин | Роль | Возможности |
   |---|---|---|
   | `admin` | Әкімші | Создание/редактирование/удаление пользователей и предметов |
   | `teacher1` | Оқытушы | Выставление и редактирование **своих** оценок |
   | `student1` | Студент | Просмотр **только своих** оценок |

`py set_passwords.py` попросит пароль для каждого из трёх аккаунтов. При вводе символы не отображаются — так и должно быть. **Не используй `TEST_ONLY`: это не пароль.** Все существующие пользователи, предмет и оценка 92 сохранены.

Если пароль уже был установлен, скрипт его не меняет. Для сброса конкретного пароля в терминале:

```powershell
py set_passwords.py --user student1 --reset
```

Остановка сервера — **Ctrl+C** в терминале.

Если `py` не работает, замени `py` на `python`.

## Как работает

Браузер → FastAPI (`app.py`) → SQLite (`ак.db`) → HTML (Jinja2). Миграции ведут версию схемы (`schema_migrations`); рабочие таблицы — `users`, `students`, `subjects`, `grades`, а также `auth_attempts` для общего rate limiter.

- **Администратор:** создаёт пользователей с ролями, редактирует логины/имена/роли/пароли/группы, удаляет пользователей без исторических оценок; добавляет, редактирует и удаляет предметы.
- **Преподаватель:** видит свои предметы и оценки, может добавлять, исправлять и удалять оценки только для собственных предметов.
- **Студент:** видит только свою группу, предметы, оценки и средний балл.

Удаление аккаунтов с оценками и предметов с оценками ограничено, чтобы избежать случайной потери истории. Чтобы удалить учителя с предметами, сначала переназначь предметы другому учителю.

## Безопасность

- Пароли сохраняются как **Argon2-хеши**, открытых паролей в БД нет.
- После входа используется подписанная сессия (`itsdangerous` / Starlette), Secure cookie в production и HMAC-штамп для отзыва старых сессий после смены пароля.
- Сервер проверяет роль **при каждом запросе**, а не только скрывает кнопки.
- Попытки входа ограничиваются по логину и IP, счётчики лежат в общей SQLite базе; все отказы имеют одинаковый текст.
- На ответах установлены CSP, `nosniff`, Referrer-Policy и production HSTS. Preview iframe режим использует `SameSite=None; Secure`.
- Изменения выполняются POST-запросами с защитой **CSRF**.
- SQL-запросы параметризованы, HTML автоматически экранируется.
- Секрет сессии автоматически создаётся в скрытом файле `.session_secret` при первом локальном запуске. Не публикуй его.

**Важно:** по умолчанию проект настроен для **локальной учебной демонстрации**. Перед публикацией в интернет понадобятся HTTPS, настройка `SESSION_SECRET` (не менее 32 случайных символов), `COOKIE_SECURE=1`, ограничение количества попыток входа, резервные копии и серверная инфраструктура. Не размещай `ак.db` в публичной папке сайта и не публикуй проект с реальными персональными данными.

## Проверка тестов

После установки зависимостей проекта и `pytest` с `httpx` из официального PyPI:

```powershell
py -m pip install --index-url https://pypi.org/simple pytest httpx
py -m pytest -q
```

Тесты работают с **временной копией** базы, оригинальный `ак.db` не меняется.

## Примечания

- Файл БД `ак.db` намеренно сохранён под исходным именем и с исходной структурой.
- `connect.py` оставлен как пример первого подключения к SQLite, для запуска сайта нужен `app.py`.

## Дополнительные проверки №10

При установленном Node.js:

```text
node --check static/lab10.js
node tests/check_lab10_logic.cjs
```

Это проверка JS-логики, а не браузера. Готовый браузерный сценарий находится в `tests/check_lab10_browser.py`, инструкции и ограничения — в `docs/VERIFICATION.md`. Для ручной проверки не нужны Node или Playwright, достаточно обычного браузера и запущенного FastAPI.

Не открывайте Jinja2-шаблоны двойным кликом как file://: сайт должен быть запущен через Uvicorn. Везде используйте одинаковый адрес и порт, чтобы localStorage был общим для двух страниц.
