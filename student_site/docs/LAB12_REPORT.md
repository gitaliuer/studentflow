# Зертханалық жұмыс 12. Қауіпсіздік механизмдері

## Мақсаты мен іске асырылған мүмкіндіктер

StudentFlow жүйесінде қауіпсіз тіркелу/кіру, рөлге негізделген рұқсат, маршруттарды сервер жағында шектеу, CSRF қорғанысы және параметрленген SQLite сұраулары бар.

### 1. Аутентификация және тіркелу

- `/register` беті аты-жөнін, логинін, оқу тобын және екі рет енгізілген құпиясөзді қабылдайды. Тіркелген соң сессия жаңартылып, студент бірден кабинетке кіреді.
- `/account` бетінде ағымдағы парольді растағаннан кейін құпиясөзді ауыстыруға болады; пароль хэші өзгергенде бұрынғы сессиялар да жарамсыз болады.
- Қолданушының рөлі клиент формасынан алынбайды: сервер жаңа аккаунтты әрқашан `student` ретінде жасайды.
- `valid_password()` Argon2 (`argon2-cffi`) хэшін сақтайды; бастапқы пароль базаға жазылмайды.
- `/login` хэшті `PASSWORDS.verify()` арқылы салыстырады. Сәтті кіруден кейін session жаңартылып, кездейсоқ CSRF токені жасалады.
- Логин бірегейлігі SQLite шектеуі арқылы тексеріледі; пароль ұзындығы 8–200 таңба.

### 2. Рөлдер (RBAC)

Дерекқордағы `users.role` бағанының бар мәндері: `admin`, `teacher`, `student`. Жаңа өзіндік тіркелу тек `student` рөлін береді. `admin` рөлін бар аккаунтқа әкімші панелінен (`/admin/users`) тағайындауға болады. Әкімші панеліндегі пайдаланушылар тізімі рөлдерді көрсетеді.

| Рөл | Рұқсат |
|---|---|
| `admin` | Пайдаланушылар мен пәндерді басқару |
| `teacher` | Өз пәндеріне баға қою және өзгерту |
| `student` | Тек өзінің бағаларын қарау |

### 3. Маршруттарды қорғау

- `/admin` бетіне кірмеген адам `/login` бетіне бағытталады; кірген, бірақ admin емес адам `/dashboard` арқылы өзінің кабинетіне қайтарылады.
- Мұғалім/студент маршруттары серверде `require_role()` арқылы тексеріледі. UI әкімшілік мәзірлерді рөлге қарай көрсетпейді, бірақ интерфейсті жасыру жалғыз қорғаныс емес.
- Өзге студенттің бағасын көру/өзгертуге болмайды; мұғалім тек өзіне бекітілген пәндердегі бағаны өңдейді.
- Өзгертетін POST формаларда сессияға байланысқан CSRF токені тексеріледі; logout POST әдісімен орындалады.
- Бір логинге 15 минутта 8, бір IP-ден 30 қате кіру әрекетіне дейін уақытша шектеу қойылады. Лимитер `auth_attempts` кестесінде сақталады және бір SQLite-файлды қолданатын бірнеше процесс арасында ортақ. Бірнеше хостта бөлек дерекқор болса, Redis сияқты ортақ қойма керек.
- `nosniff`, `Referrer-Policy`, `Permissions-Policy`, CSP және production HTTPS-та HSTS тақырыптары беріледі. Production-та `SESSION_SECRET` және `COOKIE_SECURE=1` талап етіледі.

### 4. SQL-инъекциядан қорғану

Пайдаланушы енгізген мәндерді SQL жолына біріктіруге болмайды. Барлық сұраулар `?` placeholder және параметр tuple арқылы орындалады. Мысалдар:

```python
row = conn.execute(
    "SELECT id, password_hash FROM users WHERE username = ?",
    (username.strip().lower(),),
).fetchone()

result_count = conn.execute(
    "SELECT COUNT(*) FROM users WHERE username LIKE ?",
    (f"%{search}%",),
).fetchone()[0]
```

`/lab12` бетіндегі тест формасына `' OR 1=1 --` мәнін енгізіңіз. Ол SQL коды емес, жай іздеу мәтіні ретінде параметрге байланысады; тест базаға өзгеріс жасамай, сәйкес нәтиже санын көрсетеді.

## Қорғауға арналған көрсетілім реті

1. `/register` арқылы жаңа аккаунт жасаңыз; `student` рөлінің серверден автоматты берілетінін көрсетіңіз. Тіркелген соң қолданушы автоматты түрде кіріп, `/student` кабинетіне өтеді.
2. Шығып қайта кіру үшін тіркелгенде таңдаған логин мен құпиясөзді `/login` бетіне енгізіңіз.
3. Сол қолданушымен `/admin` ашыңыз: ол `/dashboard` бағытына қайтарылады; admin мәзірі көрінбейді.
4. `admin` аккаунтымен кіріп, `/admin#users` тізімінен рөлдерді және басқару әрекеттерін көрсетіңіз.
5. `/lab12` бетінде `' OR 1=1 --` енгізіп, параметрленген іздеудің қауіпсіз жұмысын көрсетіңіз.
6. Кодта `valid_password`, `PASSWORDS.verify`, `require_role`, `check_csrf` және `conn.execute(..., params)` бөліктерін түсіндіріңіз.

## Негізгі ұғымдар

**Аутентификация** — пайдаланушының кім екенін тексеру (логин және пароль). **Авторизация** — расталған пайдаланушыға қандай әрекет/бет рұқсат екенін тексеру (рөл және ресурс құқығы).

## Тексеру

Автоматтандырылған тесттер тіркелудің әдепкі рөлін, Argon2 хэшін, admin маршрутынан redirect-ті, SQL-инъекция мәтінін, CSRF және рөлдер шекарасын тексереді. Орындау командасы: `pytest -q`.
