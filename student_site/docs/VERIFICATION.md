# Проверки StudentFlow №10

Дата: 4 ноября 2026 года. Проверялся отдельный комплект `studentflow_lab10/student_site`, исходная папка и база не изменялись.

## Выполнено успешно

1. **Полный серверный набор pytest:** `16 passed, 1 warning in 2.19s`.
   - Исходные тесты: вход/выход, границы ролей, CSRF, CRUD пользователей и предметов, управление оценками только своего преподавателя, приватность оценок студентов, диапазон оценки, защита истории, Argon2.
   - Новые тесты: каждая из трёх страниц №10 требует входа; все три роли имеют доступ; навигационные ссылки есть; GET-страницы не меняют SQLite; POST на страницы №10 не поддерживается; JS подключён отдельно, каталог не захардкожен HTML-карточками.
   - Все изменения в этих тестах выполнялись только во временных копиях SQLite. Пароли исходной и итоговой базы не менялись.
   - Предупреждение: установленная версия Starlette объявляет использование httpx в TestClient устаревшим и рекомендует httpx2. Это предупреждение, тесты завершились успешно. Дополнительный пакет не устанавливался.
2. **12 функциональных проверок JavaScript через встроенный Node VM:** `node tests/check_lab10_logic.cjs`.
   - Уникальные темы, допустимые и недопустимые часы, строго строковый priority, неизвестный/XSS courseId, лишние поля, пустое хранилище, JSON roundtrip, повреждённый/слишком большой JSON, версия, дубликаты, SecurityError.
   - Это проверки логики с имитированным localStorage, не браузер и не DOM-визуализация.
3. **Синтаксис JS:** `node --check static/lab10.js`, `node --check static/app.js`.
4. **Синтаксис Python:** все `.py` разобраны через `ast.parse`; app.py также компилировался.
5. **Jinja2:** все исходные и новые шаблоны разобраны; три новые страницы отрендерены с учебным тестовым контекстом.
6. **SQLite:** `PRAGMA integrity_check` → `ok`; `PRAGMA foreign_key_check` → пустой результат.
7. **База побайтово сохранена:** SHA-256 исходного и итогового `ак.db` совпадает:
   `0f029e03af77d738f6ae21004974da9fa6d26b0038ce56731586ce12ad0979df`.
8. **Регрессия серверного кода:** после исключения трёх новых GET-обработчиков структура AST app.py совпадает с исходной. Схема БД и существующие SQL-запросы не менялись. Дополнительные индексы не добавлялись: модуль №10 вообще не запрашивает таблицы предметов/оценок для своего плана.
9. **Зависимости:** после явного разрешения пользователя установлены из официального PyPI в отдельное тестовое venv. `pip check` → `No broken requirements found`. Точные версии сохранены в `test_environment_versions.txt`; это снимок тестовой Linux-среды, а не переносимый lock-файл установки для Windows.

## Не выполнено / заблокировано

- **Реальный браузерный прогон и скриншоты:** установленный Chromium не запустился в ограниченном окружении (`socket() failed: Operation not permitted`). Поддерживаемый запуск с расширенными разрешениями также завершился ошибкой настройки рабочей среды до запуска программы. Скриншотов нет, успешная UI-проверка не заявляется.
- Ручная проверка вида страниц, мобильного меню, фактического поведения браузера после Back/Forward, localStorage между настоящими вкладками и визуальной доступности ещё нужна.
- Запуск Uvicorn через TCP и внешняя публикация не проверялись. Маршруты проверены FastAPI TestClient без сетевого сервера. Проект не публиковался и не переводился в статический хостинг.

## Как повторить серверные проверки

Из папки student_site с установленными зависимостями:

```text
python -m pytest -q
node --check static/lab10.js
node tests/check_lab10_logic.cjs
```

Секрет сессии для локального запуска создаётся существующим кодом в `.session_secret`; не включайте его в публичные архивы. В нашей проверке использовалась временная переменная окружения, секрет в комплект не записан.

## Подготовленный браузерный тест

Требуются уже установленные Jinja2, Playwright и браузер Chromium. В проект они не добавлены как обязательные зависимости. Скрипты ничего не скачивают и не устанавливают:

```text
python tests/render_lab10_fixture.py /tmp/studentflow-ui
python tests/check_lab10_browser.py --fixtures /tmp/studentflow-ui --chromium /usr/bin/chromium
```

В Windows используйте собственные пути к временной папке и установленному Chrome/Chromium. Не устанавливайте дополнительное ПО, если не доверяете его источнику.

Покрытие подготовленного теста: карточки и форма, отдельная страница, обновление, повторный submit, неверные часы, суммы, карта/Back, события другой вкладки, отмена/подтверждение очистки, сохранность других ключей, повреждённый JSON и XSS-поля, ошибка записи, ширина 390 px, мобильное меню, блокировка localStorage.

Этот тест работает с настоящими шаблонами и JS, но с локально подставляемыми HTML-ответами на тестовом origin. Он **не проверяет** вход, FastAPI или SQLite. Даже после его успешного прогона отдельно выполните ручные сценарии `SCREENSHOT_SCENARIOS.md` на запущенном сервере.
