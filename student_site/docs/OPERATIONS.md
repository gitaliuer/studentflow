# StudentFlow: эксплуатация и выпуск

## База и миграции

При запуске FastAPI выполняет SQL-файлы `migrations/NNNN_*.sql` по порядку. Применённые версии записываются в `schema_migrations`; каждая миграция запускается внутри транзакции и повторно не применяется. Миграции безопасны для исходной учебной базы: существующие пользователи, предметы и оценки сохраняются.

Перед обновлением приложения сначала сделайте резервную копию. Для проверки применённых версий:

```sql
SELECT version, applied_at FROM schema_migrations ORDER BY version;
```

## Резервные копии

Разовая копия с проверкой SQLite `integrity_check`:

```bash
cd student_site
python backup_db.py
```

По умолчанию создаётся `backups/studentflow-<UTC>.db`; копии старше 30 дней удаляются после успешной проверки новой копии. Можно изменить срок: `python backup_db.py --keep-days 60`. Для нестандартного пути: `python backup_db.py /safe/path/studentflow.db`.

### Расписание Linux

Скопируйте шаблон `deploy/studentflow-backup.cron.example`, замените пути на абсолютные и установите задачу командой `crontab -e`. Убедитесь, что пользователь cron имеет право читать базу и писать в каталог копий. Следите за логом команды.

### Расписание Windows

Откройте **Task Scheduler → Create Basic Task**:

1. Название: `StudentFlow database backup`; триггер — ежедневно, например в 02:00.
2. Action: Start a program; Program — путь к `py.exe` (обычно `where py` в командной строке).
3. Arguments — полный путь к `student_site/backup_db.py --keep-days 30`.
4. Проверьте вкладку History и наличие нового файла в `student_site/backups/`.

### Восстановление

1. Остановите приложение и сохраните текущий `ак.db` отдельно.
2. Выберите последнюю резервную копию, проверьте её командой `python -c "import sqlite3; c=sqlite3.connect('path/to/backup.db'); print(c.execute('PRAGMA integrity_check').fetchone())"`.
3. Скопируйте проверенную копию как `ак.db`, сохранив права доступа.
4. Запустите сайт; миграции проверят инициализацию схемы. Проверьте `/healthz` и основные кабинеты.

Не храните единственную резервную копию на том же диске/хосте, что и рабочую базу. Для реальной production-системы копии нужно также переносить в отдельное защищённое хранилище.

## Переменные окружения

`APP_ENV=production` требует `SESSION_SECRET` не короче 32 символов и `COOKIE_SECURE=1`. Образец находится в `.env.example`; реальный `.env` и секреты не коммитить. `COOKIE_SAMESITE=none` используйте только когда сайт встраивается в cross-site iframe и только вместе с HTTPS/Secure cookie.

`CSP_FRAME_ANCESTORS` задаёт разрешённые источники встраивания (через пробел). В production по умолчанию используется `'self'`; пустое значение запрещено. Для запрета встраивания используйте `'none'`, а для preview укажите конкретный доверенный HTTPS-origin родительской страницы. В development без этой переменной директива опускается, чтобы встроенный preview работал. Настройки из `.env.example` нужно передать окружению процесса: приложение не читает `.env` автоматически.

`STUDENTFLOW_DB` позволяет явно указать путь к базе (например, для тестового/изолированного запуска). По умолчанию используется исходная `ак.db` рядом с `app.py`.

## Проверка перед выпуском

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check app.py migrations.py backup_db.py tests
python -m playwright install chromium
python tests/e2e_studentflow.py
node tests/check_lab10_logic.cjs
```

CI выполняет тот же набор проверок. E2E запускает отдельный сервер и временную копию базы; исходная `ак.db` не изменяется. Локально браузер Playwright нужно установить один раз. Если Chromium уже установлен отдельно, путь можно передать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. E2E также проверяет мобильное меню и отсутствие горизонтальной прокрутки на экране 390×844.

## Масштабирование

Лимитер ошибок входа использует SQLite `auth_attempts`, поэтому состояние общее для процессов одного приложения при использовании одного файла БД. На нескольких хостах с разными локальными файлами SQLite его нужно вынести в Redis/общее хранилище. Для большого числа одновременных записей и нескольких серверов следует перейти на управляемую клиент-серверную БД и пересмотреть backup-процесс.
