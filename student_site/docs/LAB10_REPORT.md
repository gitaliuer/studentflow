# Зертханалық жұмыс №10

**Жоба:** StudentFlow — студенттерді есепке алу жүйесі  
**Тақырып:** Статикалық сайтта деректерді өңдеу және клиенттік архитектура  
**Мақсат:** беттер байланысын, JavaScript арқылы форма деректерін өңдеуді, DOM құруды және localStorage арқылы беттер арасында ақпарат алмасуды көрсету.

Талаптың көзі: берілген «10 лаб АЖЖ_10 (1).docx», 3 бет, 5 практикалық тапсырма.

## Неге жеке оқу модулі қосылды?

Бастапқы №9 жоба FastAPI, SQLite, Jinja2 және үш рөлмен жұмыс істейді. Оны статикалық сайтқа айналдыру деректер мен рөлдерді бұзар еді. Сондықтан №10 тапсырмалары сол дизайндағы «Оқу жоспары» модуліне енгізілді. Сервер HTML беттерін береді және кіруге рұқсатты тексереді; модульдің оқу деректері тек браузерде өңделеді.

Жаңа беттер:
- `/lab10`: JavaScript массивінен каталог; форма; localStorage-қа жазу.
- `/lab10/plan`: басқа бетте localStorage-тан оқу; DOM кестесі; жинақ көрсеткіштері.
- `/lab10/map`: барлық беттердің блок-схемасы және екі деректер ағыны.

Бұрынғы admin / teacher / student беттері, CRUD әрекеттері, серверлік сессия, CSRF, Argon2 және SQL сұраулары сақталған. `ак.db` бастапқы файлмен байт бойынша бірдей.

## 1-тапсырма. Architecture Map

Интерактивті блок-схема: `/lab10/map`. Толық мәтіндік карта: `NAVIGATION.md`. Карта бастапқы кіруді, рөл бойынша бағыттауды, өңдеу беттерін, жаңа модульді және шығуды көрсетеді.

Негізгі тізбек:

```text
/ → /login → /dashboard
                  ├─ admin   → /admin → пайдаланушы / пәнді өңдеу → /admin
                  ├─ teacher → /teacher → бағаны өңдеу → /teacher
                  └─ student → /student → #grades

Әр рөлдің мәзірі → /lab10 ↔ /lab10/plan ↔ /lab10/map
Барлық қорғалған бет → POST /logout → /login
```

Егер сессия бар болса, `/` бірден `/dashboard`-қа бағыттайды. Кірусіз қорғалған бет `/login`-ге бағыттайды; бөтен рөлдің кабинетіне кіру 403 қатесін қайтарады.

## 2-тапсырма. Формадан деректерді оқу

HTML форма: `templates/lab10_editor.html`, `id="plan-form"`. Өрістер: тақырып, сағат (1–40 бүтін сан), басымдық.

Орындалатын кодтың үзіндісі (`static/lab10.js`, `initEditor`):

```javascript
form.addEventListener('submit', event => {
  event.preventDefault();
  if (!form.reportValidity()) return;
  const values = new FormData(form);
  const item = {
    courseId: String(values.get('courseId')),
    hours: Number(values.get('hours')),
    priority: String(values.get('priority'))
  };
  // validItem тексереді; содан кейін ғана JSON сақталады.
});
```

`input` және `change` оқиғалары таңдалған мәндерді форма астындағы preview-ға шығарады. Submit бет жүктелуін тоқтатады. Бір тақырып қайта сақталса, ол қайталанбай, жаңартылады.

## 3-тапсырма. Массивтен DOM құру

`COURSES` массивінде алты оқу тақырыбы бар. Каталогтың HTML контейнері бастапқыда бос. JavaScript `forEach`, `createElement`, `append` және `textContent` арқылы карточкалар мен select опцияларын құрады.

```javascript
const COURSES = [
  { id: 'html', title: 'HTML құрылымы', category: 'Веб-негіздер',
    description: 'Семантикалық тегтер, бет құрылымы және қолжетімділік.', hours: 2 },
  // CSS, JavaScript, DOM, localStorage, UI тестілеу тақырыптары...
];

function node(tag, text, className) {
  const result = document.createElement(tag);
  if (text !== undefined) result.textContent = text;
  if (className) result.className = className;
  return result;
}
```

Сақталған жоспардың кесте жолдары да JavaScript арқылы құрылады. Деректер HTML ретінде орындалмайды: `innerHTML` қолданылмайды.

## 4-тапсырма. Әртүрлі беттерде localStorage пайдалану

Кілт: `studentflow.lab10.plan.v1`.

Сақталатын JSON мысалы:

```json
{"version":1,"items":[{"courseId":"javascript","hours":5,"priority":"high"}]}
```

Бірінші бет, `/lab10`:

```javascript
window.localStorage.setItem(STORAGE_KEY, JSON.stringify({ version: 1, items }));
```

Басқа бет, `/lab10/plan` (`readPlan()` ішінде):

```javascript
const raw = window.localStorage.getItem(STORAGE_KEY);
const data = JSON.parse(raw);
// Нұсқа, массив, қайталанбайтын белгілі courseId,
// 1–40 бүтін hours және string priority міндетті тексеріледі.
```

Дұрыс деректер DOM кестесіне шығарылады. Бос жоспар, бүлінген JSON, шектен шыққан мәндер, бөгде өрістер, сақтауға тыйым салу және жадының толуы үшін хабарламалар бар. Бүлінген дерек автоматты түрде үстінен жазылмайды. Тазарту тек осы кілтті жояды; `localStorage.clear()` қолданылмайды.

### Шектеулер мен құпиялылық

- Жоспар origin-ге және браузер профиліне ортақ, аккаунтқа байланбайды. Басқа рөлмен кіргенде де сол оқу жоспары көрінеді. Бұл интерфейсте анық жазылған.
- Аты-жөн, топ, логин, пароль, сессия және бағалар localStorage-қа көшірілмейді. Еркін мәтін өрісі жоқ, тек алдын ала белгіленген тақырыптар қолданылады.
- Бұл модуль авторизация немесе нақты академиялық жоспарлау жүйесі емес. Браузер жады өшірілсе, жоспар жоғалады.
- Әртүрлі қойындының қалыпты өзгерістері `storage` оқиғасымен көрсетіледі. Дәл бір уақытта сақтау атомарлы емес: соңғы жазба алдыңғысын басуы мүмкін. Демонстрацияны бір белсенді қойындыдан жасаңыз.
- Басқа хост, порт немесе браузер профилі басқа localStorage болып саналады. Мысалы, `localhost:8000` мен `127.0.0.1:8000` деректері бөлек.

## 5-тапсырма. UI Testing және скриншоттар

Дәл сценарийлер: `SCREENSHOT_SCENARIOS.md`. Нақты орындалған тексерулер: `VERIFICATION.md`.

**Маңызды:** осы жинақта браузер скриншоттары жоқ. Chromium іске қосылуы орындау ортасының шектеуіне тірелді. UI тест сценарийлері мен қайта орындалатын скрипт дайын, бірақ оларды сәтті орындалған деп есептеуге болмайды. 5-тапсырманың скриншоттық дәлелін жергілікті іске қосқаннан кейін қосу қажет.

Браузерлік тест коды: `tests/check_lab10_browser.py`. Ол нақты Jinja2 шаблондарын және нақты JS-ті пайдаланады, бірақ оқшауланған fixtures режимінде серверлік кіруді тексермейді. Серверлік және рөлдік тексерулер `tests/test_app.py` ішінде бөлек.

## Қорытынды

№10 үшін навигация картасы, JavaScript формасы, массивтен DOM құру және екі бет арасында localStorage алмасуы іске асырылды. №9 серверлік архитектурасы мен бастапқы деректер сақталды. Серверлік 16 pytest және 12 JavaScript-логика тексеруі сәтті өтті. Тапсыру алдында локалды серверді браузерде ашып, UI сценарийлерін орындап, нақты скриншоттарды есепке тіркеу керек.
